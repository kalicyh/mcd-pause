# 在聊天中呈现

用已有 `catalog.json` 与本地状态生成界面：

```sh
python3 "$SKILL_DIR/scripts/mcpause.py" render --catalog work/catalog.json --out /ABSOLUTE/TASK/VIEW/mcpause.html
```

默认输出 HTML 片段。若宿主提供 visualize 能力，先读取该宿主的 visualize 指南，再按它的输出契约在回复中呈现此文件。选择当前任务允许的持久目录，使用绝对路径。没有可视化能力时展示文字候选与明确操作入口；不要宣称存在用户看不到的按钮。

交互分为四页：这一餐、续写卡、修复一餐、订单。预算与营养目标在界面内重新筛选菜单快照，核价按钮通过 `window.openai.sendFollowUpMessage` 请求一次 Codex 后续处理。宿主可能显示确认对话框。按钮不会直接请求 MCP，不会在浏览器里保存或发送 Token。普通浏览器没有宿主桥接时，会显示可复制的请求。

修改目标或搭配后，旧确认按钮停用；真正下单还需在宿主重新查询、核价并按用餐流程确认。界面状态不是交易事实来源，服务端订单响应和本地提交记录才用于后续判断。

“修复一餐”在选择的商品里检查预算、能量、蛋白和可选钠约束；营养未知就不能判定通过。“找一次替换方案”枚举一次同类商品替换，展示前后金额、蛋白变化。只在这组一次替换候选内按参考价排序，不宣称全局最优。

离线演示：

```sh
python3 "$SKILL_DIR/scripts/mcpause.py" demo --out work/mcpause-demo.html
```

演示使用 `assets/demo.json` 的虚构商品，所有对话/点餐/提醒操作在界面里禁用，仅模拟页面响应。订单页可体验支付、接单和一次本地彩纸效果，不调用宿主礼炮。演示商品编码以 DEMO 开头，不能提交给下单脚本。

分享或截图前确认界面处于演示模式。真实界面可能包含用户目标、订单取餐码和工作摘要，不能把它当成可公开的展示材料。
