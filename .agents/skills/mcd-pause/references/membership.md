# 开卡优惠与回本

用户问开卡是否划算、卡费、免配送/打包、净省或几次回本时使用。先比较，保持用户当前套餐与冰量；展示结果不代表选择开卡。无需新增服务或连接。

## 查询与试算

当前官方接口支持 `query-meals` 的 `canWithOrder` / `withOrder` 与 `calculate-price` / `create-order` 的随单购卡参数，没有独立的通用开卡接口。`query-my-account` 查询积分，不能当作持卡状态；`query-promotions` 仅适用企业团餐，不能用于普通外送的卡优惠。

1. 查询当前门店、取餐方式和预约时间的 `query-meals`，提取当次随单购卡选项：

   ```sh
   python3 "$SKILL_DIR/scripts/mcpause.py" card-options --menu work/menu.json --out work/card-options.json
   ```

   菜单 `withOrder.specId` 对应核价参数 `withOrder.membershipSpecId`；其余 `membershipCode`、`cardId`、`cardType` 按实际返回保留。餐品 `currentPrice` 不是卡费，不能据此推测开卡金额。没有可用选项时如实说明。
2. 核对 `query-meal-detail`（餐品编码参数名为 `code`），保留当前完整 `items`、套餐轮次和特调。先 `calculate-price` 不加购卡的方案，再仅增加选定 `withOrder` 试算。门店、方式、餐单、数量、特调、优惠券、餐具和预约时间保持相同。最多比较三种相关卡；不得自动换餐来制造节省。
3. 从开卡核价的 `productList` 核实新增权益卡名称、规格、数量和 `subtotal`。报价金额单位是分。确认卡费已计入 `productPrice` 和 `price`，不可再加一次；费用不完整、无法对账时保留未知。用卡后的免配送/免打包必须由对应费用字段证明，不从卡名推定全部费用都免。
4. 将两次原始请求与响应保存在任务私有目录，组装以下证据对象。`quoted_at` 使用实际查询时间；`card_product_code` 来自本次卡明细，不能硬编码上次商品编号：

   ```json
   {
     "baseline_request": {},
     "baseline_response": {},
     "card_request": {},
     "card_response": {},
     "card_product_code": "本次卡明细的 productCode",
     "quoted_at": "带时区的实际核价时间"
   }
   ```

   请求只包含核价字段，不放地址、手机号或凭据。上面的空对象是结构说明，不能直接作为真实证据。

   ```sh
   python3 "$SKILL_DIR/scripts/mcpause.py" compare-card --evidence work/card-evidence.json --out work/card-comparison.json
   ```

## 展示与计算

浏览器打开详情、加入餐单、改配或改数量后自动查询两份报价、保存 card-evidence.json 并更新页面，不要求先点击比较，不发起聊天 JSON 消息。连续修改合并查询，相同餐单一分钟内可复用报价；旧响应不能覆盖后来的搭配。详情页只展示当前搭配的价格，开卡优惠仅在“你的餐单”里按整单展示，不重复放在套餐详情下方。默认展示两种实付及扣卡费后的净省/多付，费用表、核价时间、未知权益与回本假设放在可展开详情里。没有随单卡或卡费未能核实时，明确显示原因，保留已核实的不开卡报价。

导入既有证据时，将 `--card-comparison work/card-evidence.json` 传给 prepare-browser 或 render-shop。保留当前选择；进入浏览器后自动重新查询，不把历史核价当作最新价。纯静态/聊天预览仍使用查询按钮，不声称已自动联网核价。

展示不开卡与开卡的餐品金额、开卡费、配送费、打包费、已明确的餐具费和本次实付。金额缺失显示待核实，不当成 0。基线是用户当前账号不加购卡时的实际应付，不是划线原价；已持有权益不会因此被抹去。

- 本单净省 = 不开卡实付 − 含卡费实付；为负就明确写“本单多付”。
- 本单优惠（未扣卡费）= 本单净省 + 卡费。费用分项仅用来解释这笔优惠，不再叠加一次接口 `discount`。
- 首单优惠覆盖卡费时，本次回本；否则，假设后续每次能省 R 分，回本次数 = 1 + 向上取整((卡费 − 首单优惠) / R)，包含本次用餐。R 为 0 时不能回本。

回本是情景估算。界面默认假设后续每单与本单同样优惠，并明确标注；用户可以修改假设金额。首开赠券、一次性打包减免不能宣称以后每次都有。有效期、最低消费、每日/周期次数、门店、时段及续费规则缺失时显示未核实，不能保证回本；若已知可用次数不足，说明有效期内无法按该方案回本。不建议为回本额外消费。

## 选择与确认

默认不开卡。只有用户勾选具体卡后，才把本次核实的 `withOrder` 带入新确认单；修改餐单后取消原开卡勾选。对比记录绑定当前整单和卡方案，详情页的其他查询不能覆盖购物餐单的选择。摘要包含卡名、规格、卡费、配送/打包费、含卡总额和未知权益；不使用只确认餐品的旧确认单。沿用五分钟确认和提交前核价流程，卡种或卡费变化即使总价不变也需重新确认。自动比较、回本估算或“加入这个功能”都不是实际开卡授权。
